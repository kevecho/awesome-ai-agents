# 🏥 AI智能问诊系统 - 运行指南

## 项目简介

**AI Medical Consultant**（人工智能医疗问诊系统）是一个基于 **LLM大模型 + Agent架构 + RAG检索增强** 的智能医疗问诊系统。

| 项目 | 说明 |
|------|------|
| 技术栈 | Vue3 + FastAPI + SQLAlchemy + FAISS |
| LLM模型 | DeepSeek Chat（兼容OpenAI接口） |
| Embedding | BAAI/bge-small-zh-v1.5（本地 SentenceTransformer, 512维, CUDA） |
| 向量数据库 | FAISS |
| 数据库 | SQLite（开发）/ PostgreSQL（生产） |
| 核心能力 | 智能问诊、多路检索（稠密+稀疏+RRF融合）、分诊决策、流式对话 |

## 环境要求

### 必需
- **Python 3.10+**（推荐 3.11）
- **Node.js 18+**（推荐 20 LTS）
- **npm** 或 **pnpm**

### 可选（使用 SQLite 替代时不需要）
- PostgreSQL 16（用于生产环境）
- Redis 7（用于会话缓存）

> **GPU 加速**: Embedding 模型使用 CUDA GPU 推理，需要 PyTorch CUDA 版。如无 GPU 会自动降级 CPU。

## 快速开始（本地开发）

### 第一步：安装后端依赖

```bash
cd backend
pip install -r requirements.txt
```

> **注意**：如果在 Windows 上安装 `faiss-cpu` 遇到问题，可以尝试：
> ```bash
> pip install faiss-cpu
> # 或者跳过FAISS，仅使用ChromaDB（代码会自动降级）
> ```

### 第二步：配置环境变量

后端目录中已经包含 `.env` 文件，预配置了：

- ✅ **LLM**: DeepSeek Chat API（已填入你的 API Key）
- ✅ **Embedding**: BAAI/bge-small-zh-v1.5 本地模型（512维）
- ⚠️ **数据库**: 默认使用 SQLite（已配置好，无需额外安装）

如果需要修改配置，编辑 `backend/.env` 文件。

### 第三步：选择数据库方案

#### 方案A：SQLite（默认，无需安装数据库）

修改 `backend/.env` 中的数据库配置：

```env
DATABASE_URL=sqlite+aiosqlite:///./data/medical.db
DATABASE_URL_SYNC=sqlite:///./data/medical.db
```

并在 `requirements.txt` 中添加：
```
aiosqlite==0.20.0
```

同时修改 `backend/app/models/database.py`，将数据库引擎改为 SQLite。

#### 方案B：使用 PostgreSQL + Redis（生产环境）

使用 Docker 启动 PostgreSQL 和 Redis：

```bash
docker compose up -d postgres redis
```

### 第四步：初始化医学知识库

```bash
cd backend
py -m data.medical_kb.init_kb
```

此脚本会导入示例医学知识（感冒、高血压、糖尿病、药品说明等 8 条）到 RAG 向量数据库。

如需批量导入大规模医学知识库（~29K chunks）：
```bash
py -m data.import_bulk
```

运行评测：
```bash
py -m eval.eval_retrieval --verbose    # 单轨评测（25 条标注）
py -m eval.benchmark.run --config baseline  # 双轨评测（100+30 条）
py -m eval.benchmark.generate_synthetic     # 重新生成合成集
```

清理残留数据：
```bash
py -m data.cleanup
```

### 第五步：启动后端服务

```bash
cd backend
py -m uvicorn app.main:app --host 0.0.0.0 --port 9000 --reload
```

启动成功后：
- **API 文档**: http://localhost:9000/docs
- **健康检查**: http://localhost:9000/health

### 第六步：启动前端（可选）

如果需要 Web 界面：

```bash
cd frontend
npm install
npm run dev
```

访问 http://localhost:5173

## 使用流程

### 1. 用户注册/登录

```
POST /api/v1/user/register
POST /api/v1/user/login
```

通过前端界面注册账号并登录，或者在 Swagger 文档中测试。

### 2. 创建问诊会话

```
POST /api/v1/consult/
```

每次问诊需要先创建一个会话。

### 3. 开始智能问诊

使用 WebSocket 连接进行实时流式对话：

```
ws://localhost:9000/api/ws/chat?token=<your-jwt-token>
```

发送消息格式：
```json
{
  "consultation_id": 1,
  "message": "我头疼两天了，还有点发烧，怎么办？"
}
```

Agent 处理流程：
1. **意图识别** → 判定为"问诊类"
2. **症状分析** → 提取"头痛、发烧、持续两天"
3. **追问生成** → 可能追问"有没有其他症状？""体温多少？"
4. **RAG检索** → 从医学知识库检索相关知识
5. **LLM生成** → 流式生成回复
6. **分诊建议** → 推荐就诊科室和紧急程度

### 4. 查看问诊记录

```
GET /api/v1/consult/
GET /api/v1/consult/{id}
```

### 5. 知识库检索

```
POST /api/v1/knowledge/search
{
  "query": "高血压的症状",
  "top_k": 5
}
```

### 6. 添加医学知识

```
POST /api/v1/knowledge/documents
{
  "title": "流行性感冒",
  "category": "disease",
  "content": "流行性感冒是由流感病毒引起的..."
}
```

或上传文档：
```
POST /api/v1/knowledge/upload
Content-Type: multipart/form-data
file: 医学知识.pdf
category: disease
```

## 常见问题

### 1. LLM API 调用失败

**症状**：返回"AI服务暂时不可用"

**解决**：
- 检查 `LLM_API_KEY` 是否正确
- 测试 API 连通性：
  ```bash
  curl https://api.deepseek.com/v1/models -H "Authorization: Bearer your-api-key"
  ```

### 2. Embedding 模型加载失败

**症状**：`sentence_transformers` 报错或 DashScope API 超时

**解决**：
- 首次运行会自动从 HuggingFace 下载 `BAAI/bge-small-zh-v1.5`（~92MB）
- 如果网络问题，可设置 HuggingFace 镜像：`HF_ENDPOINT=https://hf-mirror.com`
- 代码会自动降级到 DashScope API

### 3. PostgreSQL 连接失败

**症状**：`Can't connect to PostgreSQL`

**解决**：
- 检查 Docker 是否启动：`docker compose ps`
- 或切换到 SQLite（见第三步方案A）

### 4. FAISS 安装问题（Windows）

**症状**：`pip install faiss-cpu` 失败

**解决**：
```bash
# 使用 conda
conda install -c conda-forge faiss-cpu

# 或下载预编译wheel
pip install https://github.com/kyamagu/faiss-wheels/releases/download/v1.7.3/faiss_cpu-1.7.3-cp311-cp311-win_amd64.whl
```

### 5. WebSocket 连接问题

**症状**：前端无法连接 WebSocket

**解决**：
- 检查后端是否启动在 8000 端口
- 检查 `CORS_ORIGINS` 配置是否包含前端地址
- 检查 Vite 代理配置

| LLM_API_KEY | `your-deepseek-api-key` | DeepSeek API Key |
| LLM_BASE_URL | `https://api.deepseek.com` | DeepSeek API地址 |
| LLM_MODEL | `deepseek-chat` | 使用的模型 |

> ⚠️ 如需使用其他模型（如 GPT-4），只需修改 `LLM_BASE_URL` 和 `LLM_MODEL` 即可。

## 架构说明

### Agent 决策流程 & fail-closed 安全防线

#### 问诊流程

```
用户输入 → 意图识别 → ═══ 分支处理 ═══
                      ├─ 问诊类: 症状分析 → 追问/收集 → RAG检索 → LLM诊断 → 分诊
                      ├─ 查询类: RAG检索 → LLM回答
                      └─ 闲聊类: LLM直接回复
                                    ↓
                              流式输出到前端
                                    ↓
                              持久化存储消息
```

#### fail-closed 三层防线

医疗场景中，急症漏判的代价远大于误报。改造前的关键问题：LLM 输出 JSON 格式异常 → 正则解析兜底失败 → 返回伪数据 `{"error":...}` → 下游 `.get("is_emergency", False)` 默认漏判。

改造后三层纵深防御：

```
用户输入
  │
  ├─ 第 1 层：关键词预检（零延迟，LLM 调用前）
  │    33 项正则 → 命中直接返回急诊
  │
  ├─ 第 2 层：LLM 结构化输出（JSON mode）
  │    chat_structured() → response_format={"type":"json_object"}
  │    DeepSeek 保证语法合法 → json.loads → pydantic model_validate
  │
  ├─ 第 3 层：关键词兜底（LLM 漏判时补救）
  │    再次检查 → 命中修正为急症
  │
  └─ 任意层失败 → StructuredOutputError
       ├─ 症状分析失败 → is_emergency=True → 直接返回急诊
       └─ 分诊失败 → urgency="emergency"
```

| 维度 | 改造前 | 改造后 |
|---|---|---|
| 输出合法性 | 正则抠 JSON，易失败 | `response_format` 保证 + pydantic 校验 |
| 解析失败 | 返回 `{"error":...}` 伪数据 | 抛 `StructuredOutputError` |
| 急症判定 | 默认 `False`（漏判） | fail-closed 升级急症 |
| 分诊默认 | `"normal"` | `"emergency"` |

### RAG 检索流程

```
用户Query → Query Expansion（口语→医学术语）
              ├─ dict模式: 硬编码医学同义词表 (默认)
              └─ llm模式: DeepSeek改写 (延迟2.8x, 效果无提升)
                  ↓
          ┌───────┼───────┐
          ↓               ↓
      稠密检索          真BM25检索
      (FAISS向量)       (jieba分词+IDF+TF饱和k1=1.2+长度归一b=0.75)
          └───────┼───────┘
                  ↓
           RRF融合排序 (k=60)
                  ↓
           CrossEncoder Rerank
           (bge-reranker-base, 50→10)
                  ↓
            上下文组装
          (System Prompt + 知识 + 历史)
                  ↓
              LLM生成
```

### 检索增强对比 (28,585 chunks, 双轨评测)

| 实验 | 合成Hit@3 | 人工Recall@3 | 加权总分 | P50延迟 | 说明 |
|:---|---:|---:|---:|---:|:---|
| 基线 (假BM25) | 0.32 | 0.33 | 0.353 | 103ms | Dense + 字符级重叠 + RRF |
| +真BM25 | 0.50 | 0.40 | 0.445 | 78ms | jieba分词 + IDF + TF饱和 |
| +Rerank | 0.70 | 0.45 | **0.540** | 718ms | CrossEncoder精排 (50→10) |
| +LLM改写 | 0.70 | 0.44 | 0.537 | 2021ms | DeepSeek口语→术语 (不划算) |

> 最佳配置: BM25 + RRF + Rerank。**累计提升 +53%**。LLM改写延迟2.8x且分数持平，已回退。
